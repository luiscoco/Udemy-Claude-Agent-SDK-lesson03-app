03

Separate availability and approval

tools enables only Read, Edit and Glob. allowedTools pre-approves them; permissionMode acceptEdits approves editing operations.

04

Watch real tool execution

The SDK reads and edits a disposable utils.py copy. The host does not send a prewritten patch or implement a manual tool loop.

05

Print selected messages

Observe assistant text, tool names and the final SDK result. These are progress and outcome signals, not a hidden reasoning trace.

06

Verify changes independently

Compare before/after code and four host-run Python checks. SDK success alone does not prove the repair is correct.

The lesson in six steps

  1. Create the project directory.
  2. Install the SDK and choose TypeScript.
  3. Set the key in the launching shell.
  4. Create the buggy Python file.
  5. Write query with a prompt and edit options.
  6. Run, inspect the real edits, and customise deliberately.

This app uses TypeScript for the SDK host and Python for the file being repaired. Python is also required locally for the independent host checks.

A useful distinction from the tools slide

allowedTools pre-approves operations; it does not by itself restrict the available tool set. This app sets tools too. Read-only experiments should remove Edit from tools, not just from allowedTools.

The UI shows assistant explanations and tool requests. It does not expose hidden model reasoning, and tool ordering is chosen by the model.
