Trace the real repair

This illustrative sequence summarises the runtime loop. Claude chooses the actual tool order; reads and edits may repeat. Independent host checks occur after SDK completion.

Download UML SVG
01

1. Request the repair

Student → Browser + host. The prompt names utils.py and asks for crash fixes.

02

2. Reset buggy copy; run baseline checks

Browser + host → utils.py. The host copies the original bugs into a disposable working directory and records the two expected failures.

03

3. query(prompt, edit options)

Browser + host → Agent SDK. The host sets Read/Edit/Glob availability, pre-approvals and acceptEdits, then creates one query.

04

4. Send task and tool definitions

Agent SDK → Claude API. The SDK talks to Claude; the API key remains in the launching process environment.

05

5. Request Read or Glob

Claude API → Agent SDK. The model chooses how to inspect the target. Tool order is not a scripted fixture.

06

6. Read the actual Python file

Agent SDK → utils.py. The SDK executes local discovery or reading; the host hook rejects paths outside this demo target.

07

7. Return file observations to Claude

Agent SDK → Claude API. The SDK sends the actual tool observations into its next model interaction.

08

8. Request Edit for a crash bug

Claude API → Agent SDK. The model requests an edit; the prompt and contract guide the intended behaviour.

09

9. Apply the permitted edit

Agent SDK → utils.py. The SDK applies the permitted edit to the disposable utils.py. The immutable fixture is unchanged.

10

10. Finish the SDK turn sequence

Claude API → Agent SDK. The model may repeat read/edit interactions until it finishes or hits a limit.

11

11. Yield text and final SDK result

Agent SDK → Browser + host. The host receives the final result but still needs independent verification.

12

12. Read repaired file; run Python checks

Browser + host → utils.py. A trusted Python runner outside the agent directory checks normal and edge-case behaviour.

13

13. Show before/after and verified outcome

Browser + host → Student. The student compares the changed source, SDK status and four regression outcomes.
